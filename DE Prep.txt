
Data Modeling

What is Data Modeling?

Data Modeling is the process of designing how data is structured, stored, and related inside a database or data system. 
It defines entities, attributes, relationships, rules, and constraints so that data can be stored efficiently and 
used correctly by applications, analytics, or reporting systems.

In simple terms:

Data Modeling = Blueprint of how data will be organized in a system.

SCD Type 1 – Overwrite
Old data is replaced.

SCD Type 2 – Historical Tracking

What is Data Mart?

A Data Mart is a subset of a Data Warehouse designed for a specific business department or use case.
It contains focused, curated data that is optimized for a particular team like sales, marketing, finance, or HR.

Think of it like this:

Data Warehouse → Entire company data

Data Mart → Department-specific data

In Data Engineering, Data Marts help deliver clean, structured, and business-ready datasets for analytics and reporting.



1. Dependent Data Mart

This type comes from an existing Data Warehouse.

2. Independent Data Mart

This type is built directly from source systems without a warehouse.

3. Hybrid Data Mart

Combination of both:

A Data Mart is a subject-oriented subset of a Data Warehouse designed for a specific department or business function, 
optimized for faster analytics and easier access to relevant data.

What is CDC (Change Data Capture)?

CDC (Change Data Capture) is a technique used to capture and track changes (insert, update, delete) in a database 
so that only modified data is processed instead of the entire dataset.

Change Data Capture (CDC) tracks changes in source database tables and sends those changes to another system like:
Data Warehouse
Data Lake
Analytics system
Streaming platform

Instead of loading full data repeatedly, CDC loads only the changes.
1. Timestamp-Based CDC    -  Uses Last Updated Timestamp column.
2. Log-Based CDC	  -  Reads the database transaction logs to capture changes.
3. Trigger-Based CDC	  -  Database triggers track changes and store them in a separate table.
4. Snapshot-Based CDC     -  System periodically compares old snapshot vs new snapshot.


CDC in Snowflake is implemented using Streams and Tasks. 
Streams capture row-level changes (INSERT, UPDATE, DELETE) from a table, and 
Tasks automate processing of those changes to load incremental data into target tables.

Types of Streams in Snowflake
1. Standard Stream
Tracks changes in tables.

CREATE STREAM table_stream ON TABLE orders;

2. Append-Only Stream
Tracks only INSERT operations.
Useful for event logs.

CREATE STREAM append_stream
ON TABLE logs
APPEND_ONLY = TRUE;

3. Streams on Views
Tracks changes from underlying tables through a view.
