1️⃣  Streams in Snowflake
What is a Stream?

A Stream is a Change Data Capture (CDC) mechanism that tracks changes made to a table.

It records:

INSERT

UPDATE

DELETE

Streams capture delta changes since the last consumption.

Why Streams are Used

Used for incremental data processing in ETL pipelines.

	Instead of processing the entire table, you process only changed data.

How Streams Work

Stream stores metadata of changes using table versioning.

Example flow:

Source Table
     │
     ▼
Stream (captures changes)
     │
     ▼
Task / ETL Process
     │
     ▼
Target Table
Example

Create Stream

CREATE STREAM orders_stream
ON TABLE orders;

Query changes

SELECT * FROM orders_stream;

Columns added automatically:

METADATA$ACTION

METADATA$ISUPDATE

METADATA$ROW_ID

Interview Tip

Streams are commonly used with Tasks for automation.




2️⃣ Tasks in Snowflake
What is a Task?

A Task is a scheduler used to automate SQL operations.

It works similar to cron jobs.

Why Tasks are Used

To automate:

ETL pipelines
Data transformations
Incremental processing

Example
CREATE TASK load_sales_task
WAREHOUSE = compute_wh
SCHEDULE = '1 HOUR'
AS
INSERT INTO sales_summary
SELECT * FROM sales_stream;

This runs every 1 hour.

Task + Stream Pipeline
Source Table
     │
     ▼
Stream
     │
     ▼
Task (scheduled job)
     │
     ▼
Target Table

This creates fully automated pipelines.

Types of Tasks

Scheduled Tasks

Triggered Tasks

Task Trees (Dependencies)

Example:

Task A → Task B → Task C





3️⃣ Materialized Views
What is a Materialized View?

A Materialized View (MV) stores pre-computed query results.

Unlike normal views, results are physically stored.

Why Materialized Views are Used

To improve performance for frequently executed complex queries.

Example scenarios:

Aggregations

Large joins

Reporting dashboards

Example
CREATE MATERIALIZED VIEW sales_mv AS
SELECT region, SUM(amount)
FROM sales
GROUP BY region;

Query becomes faster because aggregation is precomputed.

Important Points
Feature	Description
Storage	Consumes storage
Maintenance	Automatically refreshed
Performance	Much faster queries
Interview Tip

Materialized Views are ideal for BI dashboards like:

Tableau

Microsoft Power BI






4️⃣ Snowpipe
What is Snowpipe?

Snowpipe is a continuous data ingestion service.

It loads data automatically when new files arrive.

Why Snowpipe is Used

For near real-time ingestion.

Traditional approach:

Manual COPY command

Snowpipe approach:

File arrival → Auto ingestion
Example Architecture
Application
     │
     ▼
Cloud Storage (S3)
     │
     ▼
Snowpipe
     │
     ▼
Snowflake Table

Storage examples:

Amazon S3

Azure Blob Storage

Example
CREATE PIPE orders_pipe
AS
COPY INTO orders
FROM @orders_stage
FILE_FORMAT = (TYPE = CSV);
Interview Tip

Snowpipe is serverless, meaning:

No warehouse required

Auto scaling

7️⃣ Resource Monitors
What are Resource Monitors?

Resource monitors control compute cost usage.

They monitor warehouse credit consumption.

Why Important

Snowflake uses pay-per-use pricing.

Without monitors → costs may explode.

Example
CREATE RESOURCE MONITOR monthly_monitor
WITH CREDIT_QUOTA = 100
TRIGGERS
ON 90 PERCENT DO NOTIFY
ON 100 PERCENT DO SUSPEND;
Actions Available
Threshold	Action
80%	Notify
90%	Alert
100%	Suspend warehouse

🔟 Data Masking
What is Data Masking?

Data masking protects sensitive data.

Example sensitive fields:

Credit card numbers

SSN

Personal information

Example
CREATE MASKING POLICY mask_ssn
AS (val STRING) 
RETURNS STRING ->
CASE
  WHEN CURRENT_ROLE() = 'ADMIN'
  THEN val
  ELSE 'XXX-XX-XXXX'
END;

Apply policy:

ALTER TABLE customers
MODIFY COLUMN ssn
SET MASKING POLICY mask_ssn;
Result
Role	Data Visible
Admin	Full SSN
Analyst	Masked

5️⃣ Difference Between Transient and Temporary Tables

Snowflake provides different table types.

Feature		Temporary Table		Transient Table
Visibility	Session only		Persistent
Time Travel	No			Limited
Fail-safe	No			No
Use Case	Temporary processing	Intermediate data
Temporary Tables

Exist only during the session

Automatically deleted when the session ends

Example:

CREATE TEMP TABLE temp_sales (
 id INT,
 amount NUMBER
);
Transient Tables

Persist beyond sessions

Used for staging or intermediate data

Example:

CREATE TRANSIENT TABLE stage_sales (
 id INT,
 amount NUMBER
);








6️⃣ What is Time Travel?

Time Travel allows you to access historical versions of data.

You can query data from the past or recover deleted records.

Example
SELECT * FROM sales

Use Cases

recover deleted tables

rollback mistakes

Edition		Retention

7️⃣ How Micro-Partitioning Works

Snowflake automatically divides tables into micro-partitions (~16 MB).

These partitions store:

column metadata
min/max values
statistics

Example

Table with 100 million rows

Table
 ├─ Micro Partition 1
 ├─ Micro Partition 2
 ├─ Micro Partition 3

Each partition contains metadata.

Benefit

When a query runs:

SELECT * FROM sales
WHERE date = '2025-01-01'

Snowflake scans only relevant partitions.

This is called partition pruning.

Result → faster queries.







8️⃣ Explain Clustering Keys

Clustering keys improve query performance on very large tables.

They help Snowflake organize micro-partitions more efficiently.

Example

Table: Sales

Queries often filter by date

SELECT *
FROM sales
WHERE order_date = '2025-02-01'

Create clustering key:

ALTER TABLE sales
CLUSTER BY (order_date);
Benefit

better partition pruning

faster queries

reduced data scanning

When to Use

Only for very large tables (TBs of data).

🔟 How Snowflake Handles Concurrency

Concurrency means multiple users running queries at the same time.

Snowflake handles this using Virtual Warehouses.

Each warehouse works independently.

Example
User 1 → Warehouse A
User 2 → Warehouse B
User 3 → Warehouse C

Queries do not compete for resources.

Multi-Cluster Warehouses

Snowflake can automatically add clusters.

Example:

Cluster 1 → Query load
Cluster 2 → Additional load
Cluster 3 → Peak traffic

This allows thousands of concurrent queries.
