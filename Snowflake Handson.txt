Snowflake Handson -


Table Types:

Permanant Table		- Default table type in Snowflake. Data is persisted and supports Time Travel + Fail-safe.
Temporary Table		- Exists only for the session. Automatically dropped when the session ends.
Transient Table		- Similar to permanent tables but no Fail-safe, only Time Travel (shorter data retention).
External Table		- Used when data is stored outside Snowflake (like AWS S3, Azure Blob, GCS).

Views Types:

Standard View	   - whenever we run *, every time Table get scan, bring the data, do the aggregation and give result to user - 
		     A logical view created from a table query.
Secured View	   - Used for data sharing and hides underlying table logic.
Materialized View  - Snowflake automatically does the aggregation at the back end, 
		     stored the data in cache and every time we run the * the data get pulled from that particular cache.
		     for faster query, for complex query execution.
		     Stores precomputed query results for faster performance.

Stages in Snowflakes:

Stages are locations used to store data files (CSV, JSON, Parquet, etc.) before loading them into tables using commands like COPY INTO. 
They act as a temporary storage area between external files and Snowflake tables.

Stage Types:

Table Stage 		Created Automatically  - A Table Stage is automatically created for every table in Snowflake. @%table_name
User Stage		Created Automatically  - A User Stage is automatically created for each Snowflake user. @~
Named Stage (External)	Created Manually       - A Named Stage is a user-created stage. Can reference internal storage or external storage (S3, Azure, GCS)
						 Most commonly used in production pipelines.



Stage Types Comparison

Stage Type	Created By	Scope			Stage Name
Table Stage	Automatically	Single table		@%table_name
User Stage	Automatically	Single user		@~
Named Stage	Manually	Shared across objects	@stage_name




File Format in Snowflake:

In Snowflake, a File Format object defines how Snowflake should read data files (CSV, JSON, Parquet, etc.) 
when loading them from a Stage into tables using commands like COPY INTO.

Creating a File Format helps avoid repeating file configuration every time you load data.

Zero Copy Cloning:

Because Snowflake does not copy the physical data. 
It only creates metadata pointers to existing micro-partitions, saving time and storage.

Object			Query
Table Clone		CREATE TABLE clone_table CLONE table_name;
Schema Clone		CREATE SCHEMA clone_schema CLONE schema_name;
Database Clone		CREATE DATABASE clone_db CLONE database_name;
Time Travel Clone	CLONE table AT (OFFSET / TIMESTAMP)
