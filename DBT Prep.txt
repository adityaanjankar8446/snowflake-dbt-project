1. What is DBT (Data Build Tool)?

dbt (data build tool) is an open-source transformation tool that enables data engineers and analytics engineers 
to transform data inside the data warehouse using SQL.

It follows the ELT approach:

Extract – using tools like Fivetran, Airbyte
Load – into warehouse like Snowflake, Google BigQuery
Transform – using DBT


Traditional ETL:
Source → ETL tool → Transform → Load → Warehouse
Modern ELT with DBT:
Source → Load into Warehouse → DBT Transform

5. DBT Models (Most Important Concept)

Models in dbt (data build tool) are SQL files that define transformations on raw data stored in a data warehouse. 
Each model represents a SELECT query that DBT compiles and executes to create tables or views in the warehouse.

A model = SQL file that creates table/view

The purpose of DBT models is to transform raw data into clean, structured, and analytics-ready datasets. 
They help implement the ELT (Extract-Load-Transform) approach where transformation happens inside the warehouse.

Example:

models/staging/stg_orders.sql

SQL:

SELECT
    order_id,
    customer_id,
    order_date,
    total_amount
FROM raw.orders

Run command:

dbt run

DBT converts SQL → table/view in Snowflake.




6. DBT Materializations

Materialization decides how DBT stores the model.

Type			Description
view			Creates view
table			Creates physical table
incremental		Loads only new data
ephemeral		Temporary model
materialized view	Database-managed view

Example:

{{ config(materialized='table') }}

SELECT * FROM raw.orders




7. Incremental Models (Very Important Interview Topic)

Used for large datasets.

Example:

{{ config(materialized='incremental') }}

SELECT *
FROM raw.orders
WHERE order_date > (
    SELECT MAX(order_date)
    FROM {{ this }}
)

Meaning:

Only new records get inserted.

Used heavily in Snowflake projects.




8. DBT Sources

Define raw source tables.

Example:

sources:
  - name: raw
    database: sales_db
    schema: raw_schema

    tables:
      - name: orders
      - name: customers

Query reference:

SELECT *
FROM {{ source('raw','orders') }}

Benefits:

lineage tracking
source testing
documentation






9. DBT Testing

DBT provides data quality tests.

Types:

1. Generic Tests

Example:

models:
  - name: dim_customers
    columns:
      - name: customer_id
        tests:
          - unique
          - not_null

2. Custom Tests

Example SQL:

SELECT customer_id
FROM dim_customers
GROUP BY customer_id
HAVING COUNT(*) > 1

Run:

dbt test





10. DBT Snapshots (Slowly Changing Dimensions)

Used to track historical changes.

Example:

{% snapshot customer_snapshot %}

{{
config(
target_schema='snapshots',
unique_key='customer_id',
strategy='timestamp',
updated_at='updated_at'
)
}}

SELECT * FROM raw.customers

{% endsnapshot %}

Captures changes in customer data over time.





11. DBT Macros (Reusable SQL)

Macros = SQL functions using Jinja

Example:

{% macro calculate_tax(amount) %}

amount * 0.18

{% endmacro %}

Usage:

17. DBT vs PySpark

19. Advanced DBT Interview Questions (Client Level)


Q1 What is ref() in DBT?

Answer:

ref() creates dependency between models.

Example:

SELECT *
FROM {{ ref('stg_orders') }}

Benefits:

automatic DAG
environment aware
schema abstraction



Q2 Difference Between Source() and Ref()
Function	Purpose
source()	raw source tables
ref()		dbt models

Example:

source() → raw layer
ref() → transformed models



Q3 What is DBT Incremental Model?

Model that processes only new records instead of full table rebuild.

Used for large tables.




Q4 What is DBT Ephemeral Model?

Temporary model used inside other models.

It does not create table.

Example:

{{ config(materialized='ephemeral') }}



Q5 What is DBT Seed?

Seeds load CSV files into warehouse.

Example:

data/country_codes.csv

Run:

dbt seed




Q6 What is DBT Snapshot Strategy?

timestamp

check

Used for SCD Type 2 tracking.




Q7 How DBT Handles Dependencies?
